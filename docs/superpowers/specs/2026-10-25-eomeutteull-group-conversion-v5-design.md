## 1. 목표

Google에서 이미 가장 많은 클릭을 얻는 모임·회식 페이지의 검색 의도와 URL을 유지하면서, 방문자가 일반 식사 예약과 단체·통대관 상담 중 맞는 행동을 바로 선택하게 한다.

최종 사용자 여정은 다음과 같다.

1. `청주 회식`, `청주 모임`, `청주 단체식사`와 관련된 검색에서 페이지를 발견한다.
2. 첫 화면에서 2명부터 한 팀 최대 52명까지 이용할 수 있다는 사실을 확인한다.
3. 12테이블·총 52석, 최대 인원 통대관 협의, 무료주차, 매운맛·간장맛이라는 방문 근거를 확인한다.
4. 일반 식사는 네이버 예약으로, 단체·통대관은 전화 상담으로 이동한다.
5. 전화 상담 전에는 희망 날짜·시간·예상 인원을 준비한다.

검색 순위, 색인 시점, 전화 연결, 네이버 예약 완료를 보장하지 않는다.

## 3. 채택한 접근

### 채택: 기존 승자 페이지의 전환 구조 개선

새 URL을 만들거나 유사 키워드 페이지를 대량 생성하지 않는다. 기존 `/stories/cheongju-group-dining`의 첫 화면, 행동 버튼, 직접 답변, 모바일 행동을 개선한다.

이 방식은 현재 13클릭·134노출의 성과를 유지하기 쉽고, 동일 검색 의도의 페이지끼리 경쟁하는 문제를 피하며, 사용자가 가장 중요한 행동을 빨리 선택하게 한다.

### 제외한 접근

- **새 단체예약 전용 페이지 추가:** 현재 페이지와 검색 의도가 겹쳐 내부 경쟁과 관리 중복이 생긴다.
- **콘텐츠 수량 우선 확대:** 실제 사진과 새로운 사실이 없는 상태에서 비슷한 글을 늘리면 사용자 가치가 낮다.
- **측정만 하고 화면 유지:** 색인 후 기다리는 것은 필요하지만 현재 첫 화면에서 일반 예약과 단체 상담의 목적이 분리되지 않아 전환 개선 기회를 놓친다.

## 5. 페이지 구조

### 5.1 첫 화면

- 눈썹글: `GROUP DINING · 청주 모임·회식`
- H1: `청주 모임·회식, 2명부터 한 팀 최대 52명까지`
- 설명: `12테이블 · 총 52석 · 최대 인원 이용 시 통대관 협의`와 날짜·시간·인원 사전 상담 안내
- 1차 행동: `단체·통대관 전화 상담`
- 2차 행동: `일반 식사 네이버 예약`

전화와 네이버 예약을 같은 의미로 보이지 않게 한다. 단체·통대관은 상담이 필요한 행동이고, 일반 식사는 네이버에서 예약 가능한 시간을 확인하는 행동이다.

### 5.2 핵심 근거

첫 화면 다음에 네 개의 짧은 근거를 제공한다.

1. 한 팀 최대 52명·12테이블·총 52석
2. 최대 인원 통대관 사전 협의·정해진 최소 조건 없음
3. 건물 뒤 무료주차·단체 차량 수 사전 상담
4. 매운맛·간장맛 선택

### 5.3 예약 방법 선택

- `일반 식사`: 네이버 예약에서 가능한 시간을 확인하고 예약한다.
- `단체·통대관`: 전화로 날짜·시간·예상 인원을 먼저 알려주면 좌석과 준비 사항을 안내한다.

특정 인원부터 전화해야 한다는 새로운 기준은 만들지 않는다.

### 5.4 상담 전 준비 정보

전화 전에 다음 세 가지를 준비하도록 안내한다.

1. 희망 날짜
2. 희망 시간
3. 예상 인원

상담 후 메뉴 선택, 좌석 구성, 통대관 여부와 준비 사항을 확정한다는 순서를 보여준다.

### 5.5 직접 답변

화면에 보이는 질문과 답변만 구조화 데이터 및 테스트의 근거로 사용한다.

- `청주에서 50명 안팎의 회식이 가능한가요?`
  - 한 팀 최대 52명까지 이용할 수 있으며 최대 인원 이용 시 통대관으로 협의한다.
- `단체 예약은 어떻게 하나요?`
  - 날짜·시간·예상 인원을 전화로 알려주면 좌석과 준비 사항을 안내한다. 일반 식사는 네이버 예약에서 가능한 시간을 확인할 수 있다.
- `단체 차량을 주차할 수 있나요?`
  - 건물 뒤 무료 지상주차장이 있으며 차량 수는 예약 전에 상담한다.

### 5.6 내부 링크와 하단 행동

메뉴, 매장, 오시는 길, FAQ, 후기 페이지로 의미 있는 일반 링크를 제공한다. 본문 마지막에는 전화 상담과 네이버 예약을 다시 제공한다.

모바일 하단 고정 행동은 기존 전화·길찾기·예약 구조를 유지한다. 페이지 본문에서는 `단체·통대관 전화 상담`과 `일반 식사 네이버 예약`이라는 구체적인 문구를 사용한다.

## 6. 컴포넌트와 데이터 경계

기존 Next.js App Router 구조와 중앙 콘텐츠 모델을 유지한다.

### 중앙 데이터

`lib/content/store.ts`는 최대 인원, 좌석, 통대관, 전화, 주차, 네이버 예약 URL 및 단체 FAQ의 단일 기준이다. 화면 컴포넌트와 JSON-LD가 별도 문자열로 같은 사실을 중복 소유하지 않는다.

### 이야기 데이터

`lib/content/stories.ts`는 모임·회식 이야기의 제목, 설명, 섹션, 이미지와 수정일을 소유한다. 일반적인 이야기 본문과 V5 전환 전용 화면 데이터의 경계를 유지한다.

### 화면

`app/stories/[slug]/page.tsx`는 기존 정적 이야기 라우트를 유지한다. `cheongju-group-dining`일 때만 승인된 V5 첫 화면, 예약 선택, 상담 준비, 직접 답변을 구성한다.

반복되는 V5 블록이 페이지 파일을 크게 만들면 다음의 작은 컴포넌트로 분리한다.

- `GroupDiningHeroActions`: 전화 상담과 네이버 예약을 의미별로 분리
- `GroupDiningProofs`: 최대 인원·통대관·주차·메뉴 근거
- `GroupBookingChoice`: 일반 예약과 단체 상담 선택
- `GroupConsultationChecklist`: 날짜·시간·예상 인원
- `GroupDiningAnswers`: 화면에 보이는 직접 답변

각 컴포넌트는 `STORE`와 승인된 FAQ 배열을 입력으로 사용하고 새 영업 사실을 내부에서 만들지 않는다.

### 분석 이벤트

- 단체·통대관 전화 상담: 기존 `group_inquiry_click`
- 일반 식사 네이버 예약: 기존 `naver_reservation_click`
- 지도: 기존 `naver_map_click`

버튼 위치를 구분하는 `placement` 값은 히어로와 본문 하단에서 서로 다르게 유지한다. 링크의 기본 동작은 분석 도구가 없거나 차단돼도 정상 동작한다.

## 7. SEO·AEO·GEO

- URL과 canonical은 `/stories/cheongju-group-dining`으로 유지한다.
- 기존 검색 의도인 `청주 모임·회식 장소`를 제목과 설명에서 유지한다.
- H1은 한 개만 사용한다.
- Article과 BreadcrumbList JSON-LD를 유지한다.
- 직접 답변이 FAQ 구조화 데이터에 추가될 경우 화면에 보이는 질문과 답변만 사용한다.
- 화면에 없는 평점, 후기 수, 예약 완료, 검색 효과를 구조화 데이터에 넣지 않는다.
- 메뉴, 매장, 오시는 길, FAQ, 후기의 내부 링크는 크롤링 가능한 `<a>` 링크로 유지한다.
- sitemap의 URL은 유지하고 실제 내용 변경일만 정확하게 갱신한다.

## 8. 반응형과 접근성

- 기준 폭은 데스크톱 1440px와 모바일 390px이다.
- 주요 행동의 높이는 최소 48px이다.
- 전화 상담과 네이버 예약은 색상만이 아니라 문구로도 구분한다.
- 키보드 포커스 순서는 제목, 전화 상담, 네이버 예약, 본문 링크, 하단 행동 순으로 자연스럽게 이어진다.
- 내부 링크와 외부 행동은 의미가 분명한 접근성 이름을 사용한다.
- 긴 제목과 전화번호가 320px 폭에서도 잘리거나 겹치지 않아야 한다.
- 모바일 하단 고정 행동이 마지막 콘텐츠를 가리지 않도록 하단 여백을 유지한다.

## 9. 오류와 대체 동작

- `NEXT_PUBLIC_GA_MEASUREMENT_ID`가 없거나 분석 요청이 차단돼도 전화와 네이버 예약 링크는 이동한다.
- 네이버 예약 URL을 확인할 수 없으면 일반 식사 예약 버튼을 숨기지 않고 공식 네이버 플레이스 링크로 대체한다.
- 전화 링크는 화면의 전화번호와 같은 `STORE.phoneHref`를 사용한다.
- 이미지가 실패해도 제목, 사실, 행동 버튼은 남는다.
- 새로운 영업 조건을 확인할 수 없으면 기존의 검증된 문구를 유지하고 구체적인 수치를 추가하지 않는다.
