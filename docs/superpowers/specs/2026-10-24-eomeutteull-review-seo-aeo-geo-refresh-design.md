# 어믜뜰 리뷰 최신화·SEO·AEO·GEO 개선 설계

작성일: 2026-10-24
상태: 사용자 설계 확정
대상 사이트: `https://eomeutteull.com`

## 1. 목표

네이버 플레이스에서 공개적으로 확인되는 최신 리뷰 지표와 반복 반응을 홈페이지에 정확하게 반영한다. 동시에 기존 V4의 검색 기반을 유지하면서 `청주갈비찜`, `청주 회식`, `청주 가족외식` 검색과 답변형·생성형 검색에서 어믜뜰의 사실 정보가 더 쉽게 발견되고 인용되도록 한다.

성과 목표는 다음과 같다.

1. 오래된 리뷰 카드와 확인일을 최신 검증값으로 교체한다.
2. 방문자가 리뷰에서 확인한 장점을 메뉴·공간·예약 정보와 연결한다.
3. 검색 엔진과 AI 시스템이 상호, 위치, 메뉴, 영업시간, 예약, 단체 이용 정보를 같은 사실로 이해하게 한다.
4. 검색 유입 뒤 네이버 예약 또는 전화 상담으로 이동하는 흐름을 강화한다.

- 승인된 온라인 후기가 없거나 설정이 누락되면 정적 리뷰 요약으로 안전하게 대체한다.
- `robots.txt`, `sitemap.xml`, canonical, Restaurant·Menu·FAQ·Breadcrumb·Article JSON-LD가 운영 중이다.
- 네이버 방문자 리뷰 비공식 스크래핑과 자동 공개는 기존 정책상 허용하지 않는다.

## 4. 선택한 접근 방식

### 4.1 검토한 방식

1. **최소 수정형**: 숫자와 카드 문구만 교체한다. 빠르지만 검색 의도와 구조화 데이터 개선 효과가 작다.
2. **페이지 대량 확장형**: 검색어마다 새 페이지를 만든다. 콘텐츠 중복과 얇은 페이지가 생길 위험이 있다.
3. **근거 중심 통합형**: 최신 리뷰 근거, 기존 핵심 페이지, 답변형 콘텐츠, 엔티티 구조화를 함께 강화한다.

### 4.2 확정 방식

사용자 승인에 따라 근거 중심 통합형을 적용한다. 승인된 Pencil V4의 레이아웃과 브랜드는 유지하고, 사실 데이터·리뷰 요약·검색 신호를 개선한다. 검색어별 유사 페이지를 추가하지 않는다.

## 5. 리뷰 최신화 설계

### 5.1 데이터 모델

`REVIEW_SNAPSHOT`을 단일 사실 원본으로 유지하되 다음 필드를 표현할 수 있게 확장한다.

- `rating`: 4.94
- `ratingCount`: 401
- `participants`: 367
- `visitorReviewCount`: 423
- `blogReviewCount`: 203
- `totalDisplayedReviewCount`: 631
- `checkedAt`: `2026-10-24`
- `sourceLabel`: `네이버 플레이스 공개 리뷰 화면`
- `sourceUrl`: 네이버 플레이스 방문자 리뷰 URL

페이지는 전체 리뷰 수와 세부 리뷰 수를 더해서 새로운 숫자를 만들지 않는다. 표시 공간이 좁은 홈에서는 평점, 참여자, 방문자 리뷰, 확인일을 우선한다. `/reviews`에서는 나머지 확인값을 설명과 함께 제공할 수 있다.

### 5.2 리뷰 요약 카드

정적 카드 3개를 아래 주제로 교체한다.

1. **부드러운 등갈비와 만족스러운 맛**
   최근 방문자 후기와 반응 집계에서 음식 맛과 고기 품질이 반복적으로 언급된다는 요약을 제공한다.
2. **샤브식 등갈비와 다양한 셀프바**
   채소와 사리를 취향대로 더해 끓이는 방식, 메밀전·임궁밥·우유빙수로 이어지는 식사 경험을 요약한다.
3. **가족외식과 회식에 편한 공간**
   넓고 깔끔한 매장, 단체 이용, 가족 방문, 친절한 응대가 반복적으로 언급된다는 내용을 요약한다.

카드는 방문자 닉네임이나 문장을 그대로 복제하지 않는다. 과장 표현과 순위 표현을 만들지 않는다. 각 카드에는 출처와 확인일, 네이버 원문 링크를 유지한다.

### 5.3 동적 온라인 후기

- NAVER API HUB 블로그 검색 결과만 자동 수집한다.
- 신규 글은 `pending` 상태로 저장한다.
- 관리자가 원문을 확인하고 승인한 글만 홈과 `/reviews`에 공개한다.
- 승인된 글이 없거나 API·DB가 실패하면 최신 정적 요약 카드를 유지한다.
- 네이버 방문자 리뷰 화면을 비공식 API 또는 자동화로 수집하지 않는다.

## 6. 페이지 설계

### 6.1 홈페이지

- 기존 V4 리뷰 카드 레이아웃을 유지한다.
- 최신 리뷰 요약 3개와 2026-10-24 확인 근거를 사용한다.
- 리뷰 영역에서 `/reviews`와 네이버 원문으로 이동할 수 있게 한다.
- 예약 CTA 우선순위를 변경하지 않는다.

### 6.2 후기 페이지 `/reviews`

- 제목과 설명을 `청주갈비찜 후기`, `청주 가족외식`, `청주 회식` 의도까지 자연스럽게 포함하도록 개선한다.
- 최신 평점·참여자·방문자 리뷰·블로그 리뷰를 확인일과 함께 표시한다.
- `최근 리뷰에서 반복된 반응`을 세 주제로 요약한다.
- 다음 질문에 첫 문장으로 직접 답하는 정보 블록을 제공한다.
  - 어믜뜰 후기에서 가장 많이 언급되는 장점은 무엇인가요?
  - 가족외식이나 회식에 적합한가요?
  - 매운 음식을 못 먹어도 이용할 수 있나요?
  - 주차와 예약, 최대 인원은 어떻게 되나요?
- 답변은 중앙 콘텐츠의 메뉴·단체·주차·예약 사실에서 파생한다.

### 6.3 관련 페이지 연결

- `/reviews`에서 `/menu`, `/stories/cheongju-group-dining`, `/stories/cheongju-galbijjim-guide`로 문맥형 내부 링크를 제공한다.
- 청주갈비찜·모임 가이드에서는 최신 후기 페이지로 연결한다.
- 같은 문구를 여러 페이지에 그대로 복제하지 않고 각 페이지의 검색 의도에 맞춰 요약한다.

## 7. SEO 설계

### 7.1 메타데이터

- 페이지마다 고유한 제목과 설명을 유지한다.
- 키워드 나열 대신 메뉴, 지역, 이용 상황, 검증된 장점을 자연스럽게 설명한다.
- Open Graph 이미지와 canonical URL을 현재 경로와 일치시킨다.

### 7.2 Restaurant 엔티티

기존 Restaurant JSON-LD를 다음 원칙으로 보강한다.

- 주소를 `streetAddress`, `addressLocality`, `addressRegion`, `addressCountry`로 분리한다.
- 정확한 우편번호와 위도·경도는 공식 지도 또는 주소 자료에서 검증된 경우에만 추가한다.
- `sameAs`에는 확인된 네이버 플레이스와 공식 SNS만 추가한다.
- 메뉴 URL, 예약 가능 여부, 전화, 영업시간, 주차·접근성은 화면의 텍스트와 일치시킨다.
- 대표 이미지는 실제 매장·음식 이미지 중 크롤링 가능한 URL을 사용한다.

### 7.3 리뷰 구조화 데이터 제한

- 제3자 네이버 리뷰 수치를 자사 `AggregateRating`으로 발행하지 않는다.
- 리뷰 카드의 요약문을 개별 `Review` 스키마로 변환하지 않는다.
- 검색결과 별점 노출을 보장하거나 암시하지 않는다.

### 7.4 사이트맵과 색인

- 하나의 전역 수정일 대신 실제로 변경된 주요 페이지의 수정일을 관리한다.
- 이번 변경에서는 `/`, `/reviews`, 관련 가이드의 수정일을 실제 배포일로 갱신한다.
- 배포 후 Google Search Console과 네이버 서치어드바이저에서 주요 URL 재수집을 요청한다.

## 8. AEO 설계

- 질문 제목 다음의 첫 문장이 완전한 직접 답변이 되게 한다.
- 가격, 주문 조건, 최대 인원, 주차, 휴무, 예약처럼 답변에 필요한 숫자를 명시한다.
- FAQ의 보이는 질문·답변과 JSON-LD를 같은 데이터에서 생성한다.
- 답변은 짧은 결론 뒤 필요한 세부 정보와 관련 페이지 링크를 제공한다.
- FAQ 리치 결과 노출을 목표로 과도한 질문을 만들지 않고 실제 방문 결정 질문만 유지한다.

## 9. GEO 설계

- 별도의 GEO 전용 스키마, `llms.txt`, 키워드 대량 생성 페이지를 추가하지 않는다.
- 공개적으로 크롤링 가능한 텍스트에 상호, 지역, 메뉴, 가격, 영업시간, 주차, 단체 규모, 예약 방법을 제공한다.
- 모든 변동 정보에는 출처 또는 확인일을 둔다.
- 어믜뜰만의 1차 정보인 샤브식 등갈비, 셀프바, 수제우유빙수, 최대 52명 통대관을 구체적으로 설명한다.
- Restaurant·WebSite·Article의 `@id`, publisher, author 관계를 일관되게 유지한다.
- 이미지 대체 텍스트와 영상 주변 설명을 실제 콘텐츠와 일치시킨다.
- AI 크롤러를 위한 별도 우회 파일을 만들지 않고 일반 검색 크롤링·내부 링크·인덱싱 상태를 건강하게 유지한다.

- Google Local Business 구조화 데이터: `https://developers.google.com/search/docs/appearance/structured-data/local-business`
- 네이버 사이트 검색 기본 가이드: `https://searchadvisor.naver.com/doc/wmt_guide_ps_websearch.pdf`
- 네이버 콘텐츠 노출·클릭: `https://searchadvisor.naver.com/guide/report-expose-ctr`

## 10. 오류와 경계 상황

- 네이버 수치를 확인할 수 없으면 이전 수치와 이전 확인일을 함께 유지한다.
- 서로 다른 리뷰 분류의 숫자를 합산해 새로운 총계를 만들지 않는다.
- 자동 블로그 수집이 실패해도 공개 페이지와 기존 승인 후기를 유지한다.
- 후기 요약 근거가 부족하면 추측하지 않고 해당 카드를 유지하거나 제거한다.
- 구조화 데이터는 화면에 없는 사실을 추가하지 않는다.
- 공식 지도 좌표, 우편번호, SNS 주소를 확인하지 못하면 스키마에서 생략한다.

## 11. 검증 계획

### 11.1 자동 검증

- 리뷰 스냅샷 필드와 확인일 테스트
- 리뷰 요약 3개의 출처·안전 표현·확인일 테스트
- 홈과 `/reviews`가 같은 중앙 데이터를 사용하는지 테스트
- Restaurant JSON-LD 주소·동일 엔티티·메뉴·예약 정보 테스트
- 리뷰 스키마 금지 조건 테스트
- 페이지별 사이트맵 수정일 테스트
- 전체 테스트, lint, 프로덕션 빌드

### 11.2 수동 검증

- 데스크톱과 390px 모바일 리뷰 영역 확인
- 홈페이지, `/reviews`, 메뉴, 청주갈비찜·모임 가이드의 내부 링크 확인
- 네이버 원문과 예약 링크 확인
- 운영 URL의 canonical, robots, sitemap, JSON-LD 확인
- 배포 후 실제 페이지의 최신 수치·문구 확인

## 12. 운영과 측정

- 리뷰 스냅샷은 월 1회 또는 주요 수치 변화 시 검수한다.
- Google Search Console에서 `청주갈비찜`, `청주 회식`, `청주 가족외식` 관련 노출·클릭을 확인한다.
- 네이버 서치어드바이저의 최근 90일 노출·클릭 보고서를 확인한다. 데이터 지연을 고려해 주 단위로 판단한다.
- 리뷰 페이지 유입과 네이버 예약·전화 CTA 클릭을 함께 비교한다.
- 검색 순위나 AI 추천 노출을 보장하지 않는다.

- 네이버 방문자 리뷰 자동 스크래핑
- 방문자 닉네임이나 리뷰 전문 복제
- 승인 없는 블로그 후기 자동 공개
