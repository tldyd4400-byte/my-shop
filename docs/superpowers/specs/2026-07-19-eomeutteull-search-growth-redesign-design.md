# 어믜뜰 검색 성장형 홈페이지 개편 설계

- 작성일: 2026-07-19
- 대상 도메인: `https://eomeutteull.com`
- 대상 매장: 어믜뜰 등갈비찜 청주봉명동본점
- 디자인 원본: `C:\vibecoding\my-shop\초안` Pencil 문서
- 상태: 화면 설계와 SEO·GEO·AEO 운영 설계 승인 완료, 구현 계획 작성 전

## 1. 목표

홈페이지를 단순 매장 소개 페이지에서 검색 유입과 네이버 예약 행동을 연결하는 검색 성장형 사이트로 개편한다.

핵심 검색어는 다음 세 개다.

- 청주봉명동맛집
- 청주갈비찜
- 청주맛집

사용자 여정은 다음과 같다.

1. 검색에서 어믜뜰을 발견한다.
2. 브랜드가 추구하는 푸짐한 한 상의 의미를 이해한다.
3. 등갈비찜에 셀프바 재료를 더해 샤브처럼 즐기는 식사 방식에 흥미를 느낀다.
4. 실제 사진, 후기, 좌석, 주차, FAQ로 방문 신뢰를 확인한다.
5. 네이버 예약, 전화 또는 길찾기로 이동한다.

검색 순위나 예약 완료를 보장하지 않는다. 확인된 정보와 실제 행동 데이터만 사용한다.

## 2. 채택한 접근

검색 주제마다 독립 URL을 제공하는 허브 앤드 스포크 구조를 사용한다. 홈 한 장에 모든 내용을 몰아넣는 방식보다 검색 의도가 명확하고, 사용자가 필요한 정보를 바로 찾을 수 있으며, 이야기 글을 추가해 검색 범위를 확장하기 쉽다.

구현은 Next.js App Router의 정적 콘텐츠 중심 구조로 한다. 별도 CMS, 관리자 화면, 데이터베이스, 결제 또는 예약 API는 만들지 않는다. 매장 측이 사진과 글, 네이버의 최신 정보를 제공하면 사실 확인, Pencil 승인, 코드 반영, Vercel 배포 순서로 운영한다.

## 3. 범위

### 포함

- 홈, 메뉴, 매장, 오시는 길, FAQ, 후기, 이야기 목록, 이야기 상세 페이지
- 공통 내비게이션, 푸터, 모바일 하단 행동 버튼
- 메인 영상과 식사 단계별 사진·영상
- 네이버 지도 이미지와 네이버 지도 외부 링크
- 페이지별 메타데이터, canonical, Open Graph
- robots.txt, sitemap.xml
- Restaurant, BreadcrumbList, Article, FAQPage 등 페이지에 맞는 JSON-LD
- Google Search Console, 네이버 서치어드바이저 점검 기준
- GA4 행동 이벤트 설계
- 반응형, 접근성, 미디어 실패 대체 화면, 배포 전 검사

### 제외

- CMS 또는 관리자 페이지
- 네이버 예약 API 연동과 예약 완료 데이터 수집
- 자체 결제, 회원가입, 로그인, 고객 데이터베이스
- 사용자가 직접 작성하는 후기 시스템
- 확인되지 않은 평점, 후기 수, 예약 혜택의 자동 동기화
- 검색 순위 보장 또는 AI 답변 노출 보장

## 4. 정보의 기준

사이트와 구조화 데이터는 같은 중앙 데이터에서 매장 정보를 읽어야 한다. 화면 문구와 JSON-LD에 서로 다른 값을 중복 입력하지 않는다.

| 전화 | 0507-1449-0004 |

가격, 영업시간, 좌석, 주차, 예약 혜택, 후기 수치는 배포 직전에 다시 확인한다. 변동 가능성이 큰 예약 혜택은 기본적으로 “네이버 예약 페이지에서 최신 혜택 확인”으로 표현한다. 매장 측이 배포 시점의 혜택을 명시적으로 재확인한 경우에만 구체적인 혜택을 표시한다.

후기는 일부만 발췌하고 네이버 원문 링크와 확인일을 표시한다. 제3자 후기 수치로 `AggregateRating`을 만들지 않는다.

## 6. 공통 컴포넌트와 경계

각 단위는 한 가지 역할만 갖고, 페이지가 데이터를 중복 소유하지 않도록 한다.

### 데이터 단위

- 매장 기본 정보: 상호, 주소, 전화, 시간, 주차, 좌석, 공식 외부 링크
- 메뉴 정보: 메뉴명, 가격, 설명, 포함 구성, 사진
- FAQ 정보: 질문, 직접 답변, 세부 설명, 확인일
- 후기 정보: 발췌문, 원문 URL, 확인일, 주제 태그
- 이야기 정보: slug, 제목, 설명, 대표 이미지, 작성일, 수정일, 본문 블록, 관련 글

### 화면 단위

- `SiteHeader`: 데스크톱 내비게이션과 예약 버튼
- `MobileActionBar`: 전화, 길찾기, 예약 고정 행동
- `HeroMedia`: 영상 또는 이미지, 오버레이, 제목, 설명, 행동 버튼
- `ProofStrip`: 지역, 셀프바, 주차, 예약 등 짧은 근거
- `ExperienceSteps`: 네 단계 사진·영상과 설명
- `MenuCards`: 매운맛·간장맛 메뉴 비교
- `ReservationCta`: 네이버 예약으로 이동하는 공통 행동
- `LocationPanel`: 실제 지도 이미지, 주소, 시간, 주차, 지도 링크
- `FaqList`: 질문과 직접 답변
- `ReviewEvidence`: 발췌, 출처, 확인일
- `StoryCard`: 이야기 목록 카드
- `JsonLd`: 페이지 데이터로 JSON-LD를 만드는 전용 단위
- `AnalyticsLink`: 외부 행동 이름과 배치 위치를 함께 기록하는 링크 단위

### 데이터 흐름

매장 측 제공 자료 → 사실 확인된 중앙 데이터 → 페이지 본문·메타데이터·JSON-LD → 정적 빌드 → Vercel 배포 순서다. JSON-LD는 화면과 같은 데이터를 사용하며 화면에 없는 사실을 추가하지 않는다.

## 8. 페이지별 설계

### 홈 `/`

1. 상단 내비게이션
2. 제공된 브랜드 영상 히어로
3. 지역·셀프바·식사 방식·예약 근거
4. 브랜드 이야기
5. 실제 사진과 영상이 적용된 네 단계 식사 경험
6. 대표 메뉴
7. 예약 행동
8. 후기 요약
9. FAQ
10. 네이버 지도와 방문 정보
11. 푸터와 모바일 하단 행동

히어로 제목은 “처음 보는 등갈비찜, 함께 끓여 더 맛있는 한 상”을 중심으로 한다. 한 화면에서 무엇을 파는지, 무엇이 다른지, 다음 행동이 무엇인지 이해할 수 있어야 한다.

### 메뉴 `/menu`

매운 등갈비찜과 간장 등갈비찜의 실제 사진, 가격, 구성, 설명을 나란히 제공한다. 메뉴 선택 후 셀프바 재료를 담아 끓이고 빙수로 마무리하는 순서를 연결한다. 재료 구성은 매장 상황에 따라 달라질 수 있음을 표시한다.

### 매장 `/store`

실제 외관, 한 상, 브랜드 월, 매장 내부 사진을 사용한다. “늘 자식 쪽으로 기울던 접시”라는 브랜드 방향과 가족 외식·소규모 모임에 적합한 공간 정보를 연결한다.

### 오시는 길 `/location`

실제 네이버 지도 이미지와 다음 정보를 첫 화면과 상세 영역에 반복 제공한다.

- 주소
- 영업시간과 휴무
- 브레이크 타임
- 주차
- 전화
- 네이버 지도 외부 링크

주차장·입구 실제 사진이 제공되면 승인된 교체 영역에 반영한다. 사진이 없을 때 다른 장소의 이미지를 사용하지 않는다.

### FAQ `/faq`

질문은 검색자가 실제로 묻는 문장으로 작성하고 첫 문장에서 직접 답한다.

- 월요일에도 영업하나요?
- 브레이크 타임이 있나요?
- 주차할 수 있나요?
- 포장이나 배달이 되나요?
- 매운맛이 걱정돼요.
- 네이버 예약 혜택이 있나요?
- 아이와 함께 갈 수 있나요?
- 단체 이용이 가능한가요?

확인되지 않은 “맵기 조절 가능”은 쓰지 않는다. 매운 등갈비찜과 간장 등갈비찜 중 선택할 수 있다고 답한다.

### 후기 `/reviews`

네이버 방문자 후기에서 반복된 반응을 색다른 한 상, 부드러운 등갈비, 골라 먹는 재미로 묶는다. 각 발췌문에는 원문 링크와 확인일을 둔다. 후기 수와 평점은 배포 직전에 검증된 경우에만 날짜와 함께 보이고, 구조화 데이터 평점으로 전환하지 않는다.

### 이야기 `/stories`

초기 이야기 네 개는 다음과 같다.

1. 처음 보는 등갈비찜, 이렇게 즐겨요
2. 청주 봉명동 가족 외식 가이드
3. 30여 종 셀프바를 즐기는 법
4. 매운맛과 간장맛, 무엇을 고를까

이야기 목록은 검색 의도, 읽는 시간, 대표 이미지, 짧은 설명을 제공한다. 상세 템플릿은 제목, 작성·수정일, 대표 이미지, 직접 답변형 도입, 본문 사진·영상, 관련 FAQ, 다음 글, 예약 행동으로 구성한다.

## 9. 미디어 설계

### 메인 영상

원본 파일은 `02_어믜뜰_영문_여자.mp4`다. 원본 약 85.7MB를 그대로 배포하지 않는다. 웹 전용 파일로 압축하고 다음 동작을 사용한다.

- 자동재생
- 무음
- 반복재생
- 모바일 인라인 재생
- 실제 한 상 사진을 poster로 제공
- 영상이 실패하거나 데이터 절약·움직임 감소 환경이면 poster를 보여줌
- 제목과 CTA를 읽을 수 있는 어두운 오버레이 제공

웹용 영상은 시각 품질을 확인하면서 720p 기준 최대 12MB를 목표로 한다. 이 용량에서 품질을 유지할 수 없으면 poster를 먼저 보여주고 페이지가 준비된 뒤 영상을 불러온다. 원본 영상의 내용이나 재생 순서를 임의로 잘라내지 않는다.

### 네 단계 자산

1. 등갈비찜 선택: `step-1-ribs.png`
2. 재료 담기: `step-2-selfbar.jpg`
3. 샤브처럼 끓이기: `step-3-shabu.mp4`
4. 빙수로 마무리: `step-4-bingsu.png`

3단계 영상에도 poster와 텍스트 대체 설명을 제공한다. 모든 이미지에는 장면을 설명하는 한국어 alt를 사용하며 키워드를 억지로 반복하지 않는다.

| `/stories` | 어믜뜰 이야기 \| 청주 맛집·등갈비찜 가이드 |
| `/stories/[slug]` | `{이야기 제목} \| 어믜뜰` |

각 페이지에는 다음을 제공한다.

- 본문과 일치하는 고유 description
- `https://eomeutteull.com` 기준 절대 canonical
- Open Graph 제목, 설명, 대표 이미지
- 사이트 이름 “어믜뜰”
- 언어 `ko-KR`
- 페이지에 하나의 명확한 H1

`meta keywords`는 사용하지 않는다.

## 11. 검색 수집과 내부 링크

- `robots.txt`는 공개 페이지 수집을 허용하고 sitemap 위치를 제공한다.
- `sitemap.xml`에는 모든 공개 정적 페이지와 이야기 상세 URL을 포함한다.
- 관리자, 임시, 미완성 페이지는 sitemap에서 제외한다.
- 홈에서 모든 주요 허브 페이지로 연결한다.
- 메뉴, FAQ, 후기, 이야기 글에서 관련 페이지와 예약 행동을 연결한다.
- 모든 내부 링크는 자바스크립트가 실패해도 의미 있는 `<a>` 링크로 남는다.
- URL은 소문자 영문과 하이픈을 사용하며 불필요한 쿼리 변형을 만들지 않는다.

## 12. 구조화 데이터

JSON-LD를 사용하며 화면과 같은 중앙 데이터를 읽는다.

| 페이지 | 타입 | 핵심 값 |
| --- | --- | --- |
| 홈 | Restaurant, WebSite | 상호, URL, 이미지, 주소, 전화, 영업시간, 메뉴 URL |
| 메뉴 | Menu, BreadcrumbList | 메뉴명, 설명, 가격, 메뉴 페이지 경로 |
| 매장 | Restaurant, BreadcrumbList | 상호, 이미지, 주소, 전화 |
| 오시는 길 | Restaurant, BreadcrumbList | 주소, 전화, 영업시간, 지도와 동일한 위치 정보 |
| FAQ | FAQPage, BreadcrumbList | 화면에 보이는 질문과 답변만 포함 |
| 후기 | BreadcrumbList | 검증되지 않은 AggregateRating 제외 |
| 이야기 목록 | CollectionPage, BreadcrumbList | 목록 제목과 URL |
| 이야기 상세 | Article, BreadcrumbList | 제목, 설명, 이미지, 작성일, 수정일, 발행 주체 |

FAQPage는 검색엔진의 내용 이해를 돕기 위해 사용한다. 일반 음식점에서 Google FAQ 리치 결과가 표시된다고 약속하지 않는다.

## 13. GEO와 AEO

별도의 AI 전용 파일이나 특별한 AI 스키마를 만들지 않는다. 색인 가능한 본문, 정확한 매장 정보, 의미 있는 내부 링크, 실제 이미지와 영상, 화면과 일치하는 구조화 데이터를 유지한다.

답변 블록은 다음 형식을 따른다.

1. 사용자가 묻는 문장을 제목으로 사용한다.
2. 첫 문장에서 짧고 직접적으로 답한다.
3. 조건, 예외, 세부 설명을 이어서 제공한다.
4. 외부 사실이면 공식 출처 링크를 제공한다.
5. 영업시간, 혜택, 후기처럼 변하는 정보에는 확인일을 둔다.

상호, 주소, 전화, 영업시간은 홈페이지, 네이버 플레이스, Google Business Profile 등 공식 채널에서 일치시킨다.

## 14. 행동 측정

Google Search Console에서는 검색어와 페이지별 노출, 클릭, CTR, 평균 위치를 본다. 네이버 서치어드바이저에서는 색인 상태, URL 검사, 수집 오류를 확인한다. 기본 비교 기간은 최근 28일과 직전 28일이다.

GA4에는 다음 행동을 기록한다.

- `naver_reservation_click`
- `naver_map_click`
- `phone_click`
- `menu_view`
- `story_read`

각 이벤트에는 가능한 범위에서 페이지 경로, 버튼 위치, 기기 유형을 함께 기록한다. 핵심 전환 지표는 검색 유입 대비 네이버 예약 버튼 클릭률이다. 네이버의 예약 완료 데이터가 연결되지 않은 상태에서는 외부 링크 클릭을 예약 완료로 계산하지 않는다.

이벤트 발생 조건은 다음과 같이 고정한다.

- 예약, 지도, 전화 이벤트: 사용자가 해당 링크를 실제로 누를 때 발생
- `menu_view`: `/menu` 페이지가 표시될 때 세션당 한 번 발생
- `story_read`: 이야기 상세에서 50% 스크롤 또는 30초 체류 중 먼저 충족한 시점에 페이지당 한 번 발생

GA4 측정 ID가 없을 때도 사이트는 정상 동작해야 한다. 측정 ID가 설정되면 이벤트가 활성화되는 구조로 한다.

## 15. 오류와 대체 동작

- 영상 실패: poster 이미지와 동일한 제목·CTA 유지
- 이미지 실패: 레이아웃이 무너지지 않는 브랜드 배경과 alt 제공
- 네이버 외부 링크 변경: 전화, 주소, 지도 검색 링크가 남도록 함
- 지도 스크립트 실패: 정적 지도 이미지, 주소, 네이버 지도 버튼 유지
- 분석 도구 차단: 예약·전화·지도 링크의 기본 동작은 계속 수행
- 구조화 데이터와 화면 값 불일치: 빌드 또는 배포 검사에서 실패 처리
- 최신 사실을 확인할 수 없음: 구체적 수치나 혜택을 숨기고 공식 네이버 페이지 확인 안내로 대체

## 16. 콘텐츠 운영

1. 매장 측이 사진, 글, 네이버의 최신 정보를 제공한다.
2. 가격, 시간, 주소, 혜택, 출처를 확인한다.
3. 모든 변경은 Pencil에서 화면과 문구를 먼저 승인받는다.
4. 승인된 내용만 구현한다.
5. 반응형, 링크, SEO, 구조화 데이터, 빌드를 검사한다.
6. Vercel로 배포한다.
7. Google과 네이버에 재수집을 요청한다.
8. 28일 단위로 검색 노출과 예약 클릭을 비교한다.

이야기는 월 1~2회가 권장 주기지만 억지로 페이지 수를 늘리지 않는다. 실제 방문자에게 도움이 되는 사진과 정보가 있을 때만 발행한다.

## 18. 검증 기준

### 기술 검색

- 모든 공개 URL이 HTTPS 200으로 응답한다.
- 각 페이지의 canonical이 의도한 절대 URL을 가리킨다.
- 페이지마다 고유한 title, description, H1이 있다.
- robots.txt와 sitemap.xml이 200으로 응답하고 유효한 콘텐츠 형식이다.
- 공개 페이지에 의도하지 않은 `noindex`가 없다.
- sitemap의 모든 URL이 실제 공개 URL과 일치한다.
- JSON-LD가 화면 정보와 일치한다.
- Rich Results Test에서 치명적 구조화 데이터 오류가 없다.

### 화면과 접근성

- 390px, 768px, 1440px에서 가로 스크롤과 콘텐츠 겹침이 없다.
- 버튼과 링크의 터치 영역이 48px 이상이다.
- 키보드로 내비게이션과 주요 CTA를 사용할 수 있다.
- 색상 대비, 포커스 표시, 이미지 alt, 영상 대체 화면이 제공된다.
- 모바일 하단 행동이 본문과 푸터를 가리지 않는다.

### 성능과 미디어

- 85.7MB 원본 영상을 그대로 배포하지 않는다.
- 영상에 poster와 실패 대체 화면이 있다.
- 화면 밖의 무거운 이미지와 영상은 지연 로딩한다.
- 이미지 크기와 포맷을 화면 용도에 맞게 최적화한다.
- 모바일 Lighthouse를 확인한다. Core Web Vitals 목표는 75번째 백분위에서 LCP 2.5초 이하, INP 200ms 이하, CLS 0.1 이하이며 초기에는 Lighthouse 실험실 수치와 배포 후 실제 데이터를 함께 본다.

### 기능과 분석

- `pnpm lint`가 통과한다.
- `pnpm build`가 통과한다.
- 전화, 길찾기, 네이버 예약, 후기 원문, 내부 링크가 올바르게 동작한다.
- GA4가 설정된 환경에서 정의한 이벤트가 한 번씩 기록된다.
- 분석 도구가 없어도 링크 동작은 동일하다.

### 배포 후

- Vercel Production 배포가 Ready 상태다.
- `https://eomeutteull.com`과 대표 하위 URL이 200을 반환한다.
- `www`는 대표 도메인으로 일관되게 리다이렉트된다.
- Google Search Console과 네이버 서치어드바이저에서 대표 URL을 검사한다.
- 배포 전후 28일 지표를 페이지와 검색어 단위로 비교한다.
